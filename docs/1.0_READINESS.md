# OpenAIRAC 1.0 Readiness Audit

Last reviewed: 2026-08-16. This document records the release checklist
against the implemented state, evidence for each item, and the
remaining known gaps. Never trust milestone reports: every item below
was re-verified against the code or against real cycle-2608 data during
this audit.

## Checklist

### 1. Cycle discovery → preload → activation is automatic and verified

- **Implemented**: cycle catalog + machine (Discovered → Preloaded →
  Active → Superseded/Expired/RolledBack), `Scheduled`/`Observed`
  orchestration, transactional `observe_cycles_conn`.
- **Verified**: `test_cycle_catalog_roundtrip_and_transitions`,
  `test_late_sync_observe_and_atomicity`, failpoint-based atomicity
  tests (`PublicationFailpoints`).
- **Notes**: activation is time-driven by temporal rows; cycle events
  never gate queries.

### 2. Reconciliation coverage includes every entity class OpenAIRAC decodes

- **Implemented**: airports, runways, navaids, waypoints, airway legs.
- **Not reconciled**: procedure legs and ILS associations have a single
  provider (FAA CIFP) — no second source exists to reconcile against.
  Documented gap, not a bug.

### 3. Bundles are signed, reproducible, and installable

- **Reproducible**: deterministic content-addressed bundles (build
  twice → same hash; test-verified).
- **Installable**: staged validated install, backup swap,
  `rollback_bundle`, preload-as-next.
- **Signed**: Ed25519 `sign_bundle`/`verify_bundle_with_trust`,
  fail-closed (no trust root → SignedTrusted rejected).
- **Gap**: no production trust root exists yet; shipped bundles remain
  `UnsignedDevelopment` by design. A production signing key must be
  provisioned outside this repository before signed releases.

### 4. Rollback works at publication, cycle, and artifact level

- **Verified**: publication rollback (raw row-insert re-publication,
  idempotent), cycle rollback (provider-scoped world diff),
  artifact-level `rollback_bundle`.

### 5. Data quality gates block releases on unresolved errors

- **Added this audit**: `build_bundle` refuses stores with validation
  errors (warnings allowed and reported).
- **Verified against real data**: the audit found and fixed a
  validate() type-string mismatch (`IlsLocalizer` vs stored `ILS-LOC`)
  that masked all 1,175 ILS association checks. Real cycle-2608 store
  now validates with **0 errors**.

### 6. FAA terminal airports/runways, ILS associations, procedure geometry

- **Airports/runways**: PA/PG decode (13,316 airports, 8,149 runway
  pairs), fail-closed pairing.
- **ILS associations**: PF-derived (1,175), localizer + glideslope
  navaids now decoded from PI records (audit fix).
- **Procedure geometry**: RF arcs (`derive_rf_arc`), holds,
  diagnostics.

## Adversarial findings fixed in this audit (v0.7/1.0)

1. **Airway MEA off-by-one**: MEA on a fix record applies to the
   segment FOLLOWING it; the decoder attached it to the incoming
   segment (V257 AADCO→VERNE: converter FL115, we emitted FL130).
2. **D-record elevation/magvar columns**: elevation cols 80-84 in
   whole feet (DBL's 11,800 ft decoded as 1,800); magvar cols 75-79
   (12.0E read as 12.01E).
3. **PI records undecoded**: 1,280 localizer records fell into the PC
   waypoint branch, fabricating 1,280 false waypoints and leaving all
   ILS localizers without rows. Now decoded with golden verification
   (position, frequency, runway, declination, elevation, glideslope
   position).
4. **validate() ILS type-string mismatch**: every association check
   failed against the wrong enum string.
5. **Cross-provider publication-id collision** could silently suppress
   one provider's data; now fails loud.
6. **XPAWY merged-row bands**: airways sharing a segment with
   different altitude bands now emit separate rows (spec: merged band
   undefined); CIFP records without H/L marker emit as low (converter
   convention).
7. **GS bearing packing**: row-6 field = glideslope angle × 100000 +
   true bearing (spec); row-4 = mag course × 360 + true; true derived
   from published course + declination, normalized mod 360.
8. **DME service class**: VOR-family U → 150, standalone DME U → 125
   (converter-verified for CDO/ADK/EEA).

## Golden compatibility harness

`openairac-export-xplane/examples/golden_compat.rs` diffs our exporter
against convert424toxplane v12.4 on the same CIFP (manual tool; needs
the converter binary).

Cycle 2608 results:
- **earth_fix.dat**: 32,431/32,431 value-identical; 0 fabricated.
- **earth_nav.dat**: 4,221 rows vs converter; 4,128 data-equivalent.
  Remaining divergences are documented and deliberate: name cosmetics
  (`NAR` prefix), U-class DME defaults, WMM-vs-published declination
  (IBWY), row-12/13 ILS-DME spec-vs-converter choice.
- **earth_awy.dat**: 13,106 shared first-segment pairs; 12,332
  value-identical; rest are converter chain-consolidation artifacts.

## Known gaps (blocking nothing, tracked)

- Unsigned development bundles (no production trust root).
- OurAirports navaids lack ICAO regions (regional authority falls back
  to world default).
- ~210k CIFP unsupported records preserved lossless in `raw` (vertical
  angle GP legs, course-C DF legs, MSA sectors not yet interpreted).
- PG runway width/heading unverified → `None` (never fabricated).
- No live simulator installation; the native exporter is validated by
  the golden harness, not by loading into X-Plane.
- MSFS 2024 support is a future milestone (roadmap v0.7+, not part of
  engine 1.0).
- Regional (non-US) procedure sources: licensing research done
  (DATA_SOURCES.md); none implemented.

## Definition of 1.0-ready

1.0 means an operator can run OpenAIRAC end-to-end for at least one
simulator with current AIRAC data: cycle discovery → preload →
activation automatic and verified; reconciliation over every decoded
entity class; bundles signed, reproducible, installable; rollback at
publication/cycle/artifact level; quality gates blocking releases on
unresolved errors; FAA terminal/ILS/procedure geometry complete.

## Release-candidate validation (cycles 2608 + 2609)

- Golden nav harness: 32,457/32,457 fixes value-identical on 2609
  (32,431/32,431 on 2608); zero fabricated rows; zero ours-only nav
  rows; 8 documented U-class DME divergences only.
- Golden procedure harness: 1,379/1,379 chains identical across
  KSFO/KDEN/KJFK/KLAX/KORD on BOTH cycles.
- Machine-enforced release gate (`scripts/release-gate.sh` +
  `openairac release-gate`): validation errors, publication audit,
  procedure referential integrity, bundle determinism, signature
  fail-closed, installer post-validation — PASS on cycle 2609.
- Isolated X-Plane 12 Custom Data smoke: transactional install,
  resolve Consistent, tamper detected, recovery verified; the
  operator's real Custom Data (Navigraph) never touched.

The engine state satisfies this definition **except the production
signing trust root**, which is a release-provisioning step, not an
engineering gap. The provisioning workflow is documented in
SECURITY.md; `openairac keygen generate` makes it the only external
release step.
